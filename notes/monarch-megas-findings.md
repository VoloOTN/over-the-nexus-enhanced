## Session 3 disassembly (2026-11-10) — tools: scratch/_ov3dis.py (ov3 base 0x02141700), scratch/_tribute_xref.py
### Confirmed (direct disassembly of otn_enhanced/reference_files/nds_overlay_3.bin; static only, NOT run live)
- CardWorkshop "tribute_*" addresses are OFFSETS INTO the summon struct 0x02298A28 (no literal of 0x02298A54/56/3E exists in ov3; 0x02298A28 has ~150 pool literals): +0x16 tribute_mode, +0x2C selected-count (halfword), +0x2E second halfword bound, +0x30.. halfword array of selected entries. Seen at 0x0225FFF4 (ldrh r6,[r1,#0x2c]; loop reads [r1+r3*2+0x30]) and 0x022600C0 (ldrh [+0x2E]).
- 0x0225FFF4(player r0, slot r1, +r2): per-candidate Tribute filter. Returns 0 (illegal) or 0x800 (legal, `movs r0,#2; lsls r0,#10`). It rejects slots>4, empty zone, a candidate already in the selected list, and calls 0x021AD870/0x021AD488.
- 0x021AD488 = `r2=1; bx 0x021AD495` -> body 0x021AD494: a BOOLEAN legality check (returns 0 or 1; epilogue `movs r0,#1`/`movs r0,#0`) scanning kind-0x40 nodes at zone+0xA0C and a cid switch {0x17EE,0xEB7,0x1432,0x1DBE,0x1C0B,0x1E86}. It is NOT a Tribute-value (1-vs-2) function. In 0x022600C0 its results are summed into r5, so r5 counts legal Tributes; where "counts as 2" would be applied is NOT yet found.
### Ruled Out
- "0x021AD488 returns how many Tributes the monster counts for": false, it is boolean.
### Open

## Session 3b (2026-11-10, static, ov3)
### Confirmed by disassembly (not live)
- 0x0225CE0C(player, cid, mode, slot-ish, stack: +0x68->[+0x12], +0x6C->[+0x2E]=NEED count, +0x70=callback) INITIALISES the summon struct 0x02298A28 (+0x00/+0x02 player, +0x0E cid, +0x16 mode, +0x2C=0, +0x2E=need, +0x06, +0x12) then runs picker 0x0219DA2C. 26 callers (0x225d2bc .. 0x225ff52): each Summon/Set/Tribute-type path passes its own need.
- Normal-summon legality fn 0x0225D1E4(player, slot): cid = 14-bit field of [0x0229C33C + slot*8]; level via 0x021B20AC(player,slot); need = (level>=5) + (level>=7) (asm 0x225d22a..0x225d23c); if need>=2 and 0x021AC204(0x1E03) true then need-1; legal iff 0x021ACC10(player, 0x19B2, need) > 0. Gate: 0x021B9E84 nonzero, and 0x021AC204(0x1EB1) must be false unless attribute-of-cid == 2.
- Picker 0x02260210 (per-candidate, uses 0x0225FFF4): adds the candidate to the selected list at 0x02298A58 (halfword per entry = card id of the monster), then if mode(+0x16)==0 and 0x021AE148(player, summoned cid +0x0E, side, slot) is TRUE it adds the SAME monster a SECOND time (+0x2C incremented again) = native "this monster counts as 2 Tributes".
- 0x021AE148 is the native double-Tribute predicate: switch on the candidate monster's cid {0x1C2D, 0x17E9±1, 0x1521, 0x17E9-0x51, 0x17E9+0x8A/0x8B, 0x1DA1.., 0x2364, 0x1FCF, 0x24A8, ...}; some arms compare get_attribute(summoned cid) == get_attribute(candidate) (0x0202ABC8) = "counts as 2 Tributes for a monster of the same Attribute". => Restoration ("equipped monster counts as 2 Tributes") and The First Monarch (deferred) need only a front on 0x021AE148; NO new picker machinery.
### Consequence for the plan (still UNPROVEN live)
- M0 ("Tribute Summon this by Tributing 1 Tribute Summoned monster") = override need to 1 for the 6 Mega cids at the 0x0225D1E4 need computation AND restrict the single Tribute candidate to Tribute Summoned monsters (0x0225FFF4/0x02260210 filter). Needs a per-monster "was Tribute Summoned" status: NOT located yet.

## Session 5b: M0 DESIGN PROPOSAL (static; UNPROVEN live)

One real Tribute-summon legality/selection engine is the picker 0x02260210 + filter 0x0225FFF4.
- **Proposed M0 = "a Tribute Summoned monster counts as 2 Tributes for a Mega"**: front 0x021AE148(player, summonedCid, side, slot) so it returns TRUE when summonedCid is one of the six Mega cids AND the candidate's flag word ([0x0229ACD8+side*0xB3C+slot*0x14], same word it already loads) has bit 3. Megas are Level 8 -> need 2 -> one such candidate satisfies it; the normal 2-any-Tributes route stays. No need override, no picker change; the picker (0x02260272) already double-lists a monster when this predicate is true; the legality polling goes through the same code. UNPROVEN: that legality polling (0x0225E3F0 area) also routes through 0x021AE148 (check in a GDB trace by breaking on 0x021AE148 during a CPU duel).
- Restoration ("equipped monster counts as 2 Tributes") = same front, keyed on the equip link.
- E2 (attribute of the Tributed monster) needs the entry list [0x02298A28+0x30..] read at the Tribute commit (0x02266F7E / 0x02262574).
- Mega cids and levels must be re-derived from carddb (earlier id list was wrong).
